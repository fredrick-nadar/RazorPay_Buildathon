# September 3 intake checkpoint

This is a development checkpoint, not a production release or a newly certified
Phase 7 submission. The governing PRD and BUILD_STATUS are unchanged.

## Supported workflow

1. Connect using Razorpay Test Mode key ID and secret. Import orders, payments,
   refunds, settlement summaries and settlement-reconciliation rows for a date
   range. Credentials are request-scoped, not stored with the import.
2. Preserve the official response as immutable gateway evidence. Orders alone
   are not captured payments; empty settlement feeds are not fabricated as
   official Razorpay responses.
3. If eligible Test Mode payments lack settlement evidence, explicitly generate
   labelled synthetic gateway evidence. The current action creates only payment,
   refund and settlement source revisions, never bank or ledger files.
4. Upload bank and merchant-ledger CSVs separately; review column mapping before
   validation. Existing uploads are preserved. Legacy automatically generated
   merchant files do not satisfy this upload requirement.
5. Reconcile when all three source groups are ready. Readiness means sources are
   present, not that they agree. Quarantine, unresolved cases, deterministic
   verification, dry-runs and explicit human approval remain enforced.

The UI uses `/api/v1/razorpay/imports/{id}/generate-gateway-evidence`. A backend
without that route produces an explicit upgrade/restart message, with no fallback
to older five-source generation. Restart a non-reloading backend after upgrades;
do not clear the database. The schema migration preserves legacy demo history.

The compact dialog retains the existing fonts and monochrome palette, displays
saved merchant filenames/provenance, and places technical details behind
expandable sections. Source readiness and synthetic/non-production warnings
remain visible.

## Reproducible sample and record counts

See [the companion scenario](../../demo_scenarios/rzp_companions_v1/README.md).
It has 60 payment records and a verified 144 eligible economic source records,
not 500 payment transactions. Its settlement, bank and ledger evidence is
synthetic. The two merchant CSVs are the only manual uploads required.

The master matrix is a filtered payment-centric view requiring match information
and settlement/bank/ledger links. Its row count is not the eligible count across
all five source types, and record participation in matching is not proof that all
related exceptions are closed. Missing bank evidence for one settlement can
exclude many payment rows from the matrix.

For a larger official Test Mode dataset, complete additional Test Mode Checkout
payments and verify their captured status; adding orders or local CSV rows does
not populate Razorpay's Payments API. The existing lifecycle helper,
`scripts/seed_razorpay_test_lifecycle.py`, currently accepts 1-100 payments per
state file. Larger totals require bounded separate batches and enough compatible
unused orders, followed by a fresh import and matching companion scenario.
No larger batch was generated as part of this checkpoint.

## Repository hygiene

- Include implementation modules, tests, lockfiles, source fixtures, scenario
  hashes and evaluator-only labels. Do not ignore entire datasets or artifact
  trees needed for reproduction.
- Exclude credentials, local databases and SQLite sidecars, logs, caches, raw
  imports, temporary test state and the owner-requested private handoff file
  `cloud-reference.md`.
- Companion fixture bytes are protected by `.gitattributes`; their manifests
  hash the exact export bytes, regardless of Windows `core.autocrlf`.
- Obsolete OCR/PDF extraction code and old demo samples remain removed. The
  schema-mapping CSV examples remain useful and are retained.
- The historical ideation snapshot was removed from the release tree; only the
  governed specifications describe supported OCR, PDF, and gateway features.

## Known limits still open

- C5 and the approximately 30-second sync/proxy timeout were addressed by the
  subsequent [September 4 import reliability checkpoint](2026-09-04-import-reliability.md).
- Real investigator-provider wiring, durable jobs and deployment/security gates
  are not certified by this checkpoint. The companion regression uses the fake
  deterministic investigator and does not prove live Groq investigation.
- Demo settlements are synthetic, not Razorpay-issued settlement evidence.
- Increasing the batch must retain meaningful exceptions, separate evaluation
  labels and honest denominators; it must not target an artificially perfect
  match rate.
